# Dashboard language

Use concrete labels and the same terms as the stored research model.

| Term | Meaning |
|---|---|
| Study | Research question, workflow and history |
| Project | Code, environment and original evidence |
| Task | Requested work with instructions and expected outputs |
| Role | Reusable working instructions |
| Agent preset | Saved harness/model settings |
| Conversation | Backend session and its context |
| Run | Recorded execution of requested work |
| Note | Saved human context; acknowledgement is a read receipt |
| Workspace question | Separate Q&A, saved in Library |
| Checkpoint | A recorded decision that governs progression |
| Room | Shared visual location used by tasks across studies |

Navigation is **Lab, Studies, Library, Workflow**. Library sections are **Outputs, Documents,
Notes & sources**. Use “By machine” for that scene layout; reserve “project machine” for execution.

Name the action: **Save note**, **Create study**, **Send**, **Review**, **Connect**, **Disconnect**.
Explain what will be downloaded, written, launched or published at the decision. A disconnected
machine may need reconnecting; say “Sign in again” only for authentication problems.

Show the task name first and its skill underneath. Use short states such as **Task unfinished**
with one recovery action. Put timing details in a tooltip and consequences in the confirmation.
Guides should give the steps and an example; explain a limitation once where it matters.

Keep optional presets and model controls expandable. Keep instructions, evidence, errors and
pending decisions readable. Remove repeated introductions, slogans and implementation jargon from
ordinary flows. Never describe a queued task as idle or imply that a read receipt promises execution.

Use movement for recorded changes of place or activity. Short gestures can show reading, searching
or editing; they do not claim progress or scientific quality. Keep the recorded state visible when
an animation is delayed, unknown or decorative. A stalled process, a question and a provider limit
need different explanations even when all three have stopped moving.
