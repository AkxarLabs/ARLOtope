# Ideate (phased pipeline)

<!-- arlotope:contract (generated by `arlo docs` from workflow/) -->
**First, load the brief:** `arlo.py brief ideate [--study <slug>]`; skip when `ARLOTOPE BRIEF /ideate` is already supplied. It states how to finish, what to produce and show the PI, and the PI's additions and checkpoints.
**Read first:** `AGENT-GUIDE.md` — "In-project method-ideation (/ideate --in-project)".
<!-- /arlotope:contract -->

For `--in-project <slug>`, read [In-project method ideation](references/in-project.md) and use
that mode instead of filing hub ideas. Ordinary ideation follows the pipeline below.

Goal: end with 1–3 filed studies whose ideas have already survived adversarial reflection — not a long
list of shallow ones. Depth knobs: `ideation.*` in `lab/config.yaml` (`candidates`, `reflection_rounds`,
`critics_per_idea`, `enable_combination`). **Critics are the named `ideation-critic` role**
(`.claude/agents/ideation-critic.md`, rendered by `tools/role_sync.py` with
`agents.critic_model`/`critic_effort` already resolved) — spawn them with
`subagent_type: ideation-critic` so the model binding and the dashboard's trace both come for free
(each critic shows up by role, with its verdict as its result). Backends without role files:
`tools/role_sync.py resolve critic` prints the `model=`/`effort=` to pass
per spawn; otherwise critics run at the session model.

## 1. Working state

Keep useful paper/source records with the knowledge command in the run brief, including URL/DOI,
version and actual reading coverage. Use this study's records when a study exists, Lab-wide records
otherwise. Retain only useful sources; the shared REFERENCES index below remains the cross-study index.

**Keep all working state** (scan queries, sketches, every critique, parentage, tournament records) in one
worksheet at `lab/ideation/<date>-<HHMMSS>-ideation.md` (`HHMMSS` keeps same-day reruns collision-free;
create `lab/ideation/` if absent). Only finalists become studies (step 3); everything else stays in the
worksheet, so a crashed/compacted session is resumable and nothing lives only in chat. Append a one-line
row to `lab/knowledge/REFERENCES.md` for each *keeper* paper a research scan surfaces (skip a bibkey
already in the index), so the reading compounds.

## 2. The pipeline

Generate at most `ideation.candidates` candidates, run at most `ideation.reflection_rounds` critique
rounds, and combine only if `ideation.enable_combination`. Spawn at most `limits.ideate_critics` critics
in all; past that, critique the remaining candidates yourself, in writing. A candidate killed along the way has any
surviving thread harvested into `lab/knowledge/OPEN-QUESTIONS.md`.

1. **Sources.**
   - *Optional human pre-step:* a `/discuss direction [topic]` session seeds a direction doc that this
     phase reads as its research-scan seed. Skip this in autonomous runs.
   - Read the lab's open questions, findings and failures. Failures are useful: "X failed because Y"
     suggests "avoid Y" ideas.
   - Skim the shared reading index. A paper already logged for a prior idea is grounding here, not
     something to re-fetch.
   - Check `arlo.py studies`, so you don't duplicate live or killed ideas.
   - **Research scan:** if the PI gave a direction, do a focused web/arXiv sweep (recent papers; what is
     saturated vs open), about 15–25 minutes with logged queries. This scan supplies raw material; it
     is not the lit review.
2. **Generate.** Before falling in love with any candidate, force the IDEA-template discipline on each:
   a one-sentence falsifiable hypothesis, the cheapest decisive experiment, and how it fails fast.
   Discard anything that can't produce all three. Seek **mechanism diversity**: candidates that differ
   only in degree count as one.
3. **Reflect.** `ideation.critics_per_idea` **`ideation-critic`** subagents **in parallel** per
   candidate, in fresh context — each receives only the candidate's hypothesis/sketch text and its
   charge, never your enthusiasm. Start each spawn's description with the charge, e.g. "Novelty
   skeptic: <candidate>", so the PI can tell the critics apart. Record each critique in the
   candidate's section of the worksheet. The charges are the role's: novelty, feasibility and, for a 3rd+
   critic, value.
4. **Evolve.** Revise each candidate to answer its critiques: sharpen the hypothesis, swap the
   infeasible component, narrow the claim. A candidate whose core is refuted (not just bruised) is
   killed now. Repeat Reflect → Evolve up to the round cap; later rounds can use single cheaper
   critics. Stop early if a round produces no substantive critique.
5. **Combine** (if enabled). Look for complementary survivors — A's mechanism with B's evaluation
   insight, or A's method on B's underexplored setting. Propose up to 2–3 combinations as new
   candidates and give each one reflect pass. Check the parents' known critiques first: a combination
   inherits them.
6. **Tournament.** Compare all survivors in pairs: round-robin if there are 6 or fewer, a bracket
   otherwise. For each pair, argue both sides briefly (novelty, feasibility on the available compute,
   impact, cost-to-signal), pick a winner and record the win or loss. Rank by record. Break ties on
   **cost-to-signal**: cheaper decisive experiments win.

## 3. Triage & file

For each of the top 1–3:

1. **File it:** `arlo.py new <slug> --title "<title>"` (add
   `--workflow <id>` only when the PI's direction names a workflow; otherwise the lab's default
   applies). It refuses a slug that already exists — killed and parked slugs are never reused (reuse
   would overwrite the recorded kill reason: silent resurrection). Pick a distinct slug for a successor
   and link the old one in the triage notes.
2. **Write `studies/<slug>/IDEA.md`** from `templates/idea/IDEA.md`: scores (novelty, feasibility,
   impact, cost-to-signal — 1–10, anchored as in the IDEA.md template, each justified in one line), the tournament record, and a "Reflection
   summary" in the triage notes (the idea's strongest surviving critique, so the literature review and
   scoping start with eyes open). Leave out the template's `state:` line; the kernel keeps where the
   study stands.
3. **Report the triage:** the idea was reflected and triaged here, so it leaves the idea step:
   `arlo.py move <slug> done --note "triaged by /ideate"`. If writing it up
   shows a critique it cannot survive, report `arlo move <slug> kill --note "<reason>"` instead, after
   harvesting any surviving thread into `OPEN-QUESTIONS.md`.

Promising-but-not-now candidates get one-line entries in `OPEN-QUESTIONS.md` (no studies). Then report:
the ranking, each finalist's hypothesis + strongest surviving critique, and which to take forward first.
If a study then waits for the PI, say so.
