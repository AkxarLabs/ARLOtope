# Finalize

<!-- arlotope:contract (generated by `arlo docs` from workflow/) -->
**First, load the brief:** `arlo.py brief finalize --study <slug>`; skip when `ARLOTOPE BRIEF /finalize` is already supplied. It states how to finish, what to produce and show the PI, and the PI's additions and checkpoints.
<!-- /arlotope:contract -->

Output: everything closed, reproducible, and harvested.

A study **without a paper** (a Quick study, or a target-driven one from `/compete`) follows
[its own variant](references/variants.md) in place of the paper-specific parts of step 1.

## Procedure

1. **Reproducibility pass on the project repo** (so others can build on it):
   - `uv run pytest` green; smoke config runs clean from a fresh `uv sync`.
   - README's Reproduce section accurate; every paper-cited run id present in `runs/registry.jsonl`; figure scripts regenerate the paper's figures.
   - **Venue mode switch:** if the paper targets a non-`generic` venue, confirm the official style file is present in `studies/<slug>/paper/` and flip the preamble from drafting → camera-ready per that venue's header comment (NeurIPS `[preprint]`→`[final]`, ACL `[review]`→final, ICLR add `\iclrfinalcopy`, ICML add `[accepted]`) — de-anonymizing the author block. Re-compile; confirm page count is within the venue limit (`templates/paper/venues/README.md`). If no style file / no LaTeX toolchain, record it as a queued PI note (a camera-ready PDF is the PI's to produce).
   - **Secure the evidence in the hub** so the paper stays auditable even if the project is later moved or cleaned: `.claude/skills/make-figures/tools/sync_figures.py <slug> --check` (hub figures match their project sources), then `.claude/skills/finalize/tools/lock_artifacts.py <slug>` (archives each cited `metrics.json` into `studies/<slug>/paper/artifacts/` and records `artifact_sha256`), then `checks/audit_claims.py studies/<slug>/paper --verify-hashes --scan-novelty --rel-tol <critique.claim_rel_tol>` — after this the paper audits from the hub alone. An unbacked **novelty WARN** (exit 2) blocks: nothing claiming "first / SOTA / outperforms all" leaves the lab without a `\cite` or lit-review pointer behind it.
   - **Final integrity check (blocking):** re-run every audit under `audits:` in `workflow/rules.yaml` on `studies/<slug>/paper`. A FAIL (exit 1) or an unresolved MANUAL (exit 2) blocks finalization — never wave it through at the last step.
   - Final commit + tag `paper-v1` **in the project repo** (it marks the code and runs the paper cites; the paper itself lives in the hub, where the camera-ready flip is committed). If publishing, this repo + the tag are the artifact.
2. **Hub close-out:**
   - `FINDINGS.md`: final confirmed findings with evidence pointers (paper section + run ids).
   - `FAILURES.md` / `OPEN-QUESTIONS.md`: harvest everything the project learned that didn't make the paper — future-work threads are next cycle's `/ideate` fuel.
   - **Verify the write-back landed:** `tools/guard.py evolve <slug>` — a WARN means the RECIPE (the reusable success recipe) wasn't distilled to `FINDINGS.md`/`NOTES.md`; fix it before going on. Then `tools/guard.py writeback <slug>` — WARN-only, confirms the rule-11 write-back landed.
   - **Procedure retrospective:** one paragraph in the lab notebook — where did the procedures (skills) fight you or fail? Propose concrete changes to the PI as added instructions: `arlo.py propose <procedure> --file <draft.md> --study <slug> --why "<what went wrong>"` (the PI takes or leaves them on the dashboard's Workflow page). This is how the lab itself improves.
   - IDEA.md: pointers to the paper PDF (or the selected run) and the project tag. Notebook entry.
3. **Report the outcome** (`arlo.py move <slug> <outcome> --note "…"`):
   - `done` — every step above passed; this finishes the study. Note: the deliverable (paper PDF or selected run id) and the project tag.
   - `audit-failed` — a blocking audit or novelty WARN in step 1 that finalization can't fix without new runs or a changed claim. Stop at the failure without tagging. Note: which audit, its exit code, and what it needs (more seeds, a dropped ablation, a claim to soften).
   - `park` — something outside the lab blocks closing (e.g. a toolchain the camera-ready needs). Note: what.

   Then report the deliverable paths, the findings recorded, and the proposed procedure improvements. Anything beyond the lab (arXiv, submission) is the PI's action — AI involvement must be disclosed per venue policy.
