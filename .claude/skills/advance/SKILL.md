# Advance One Step

<!-- arlotope:contract (generated by `arlotope docs` from workflow/) -->
**First, load the brief:** `uv run --with pyyaml python arlotope.py brief advance --study <slug>` — skip it if a `ARLOTOPE BRIEF /advance` block is already in your context. It says where the study stands, the PI's own instructions for this work, and the checkpoints.
<!-- /arlotope:contract -->

The middle autonomy mode: more hands-on than `/autopilot`, less typing than invoking each procedure
yourself. One `/advance` = **one step's procedure, then a hard stop** — the PI verifies its output before
the next `/advance`. Same procedures, same checkpoints; this skill only adds "do the next thing, then wait".

## 1. Pick the study

- **Check the inbox first:** `uv run --with pyyaml python tools/lab_bus.py inbox`. A PI directive may say
  which study to advance, or park/kill one; act on it within the protocol and ack it, then pick.
- With `<slug>`: that study.
- Without: run `uv run --with pyyaml python arlotope.py status` and take the study furthest along its
  workflow that isn't waiting for the PI, shelved or finished. If every study waits for the PI, report
  what waits and stop — that *is* the answer.

## 2. Find the procedure

`uv run --with pyyaml python arlotope.py next <slug>` prints the procedure to run. If it says the study waits
for the PI, has finished, or is shelved, report that and stop.

## 3. Run it

Run that procedure's skill for the study, start to finish, exactly as written (load its brief:
`arlotope.py brief <procedure> --study <slug>`). It does its work and reports its own outcome with
`arlotope move`; keep what `arlotope move` printed.

- One procedure only. If its outcome sends the study back (e.g. more experiments), that is the *next*
  `/advance`, not this one.
- **Never pass a checkpoint that is not approved.** If `arlotope move` says the study waits for the PI, or the
  procedure stopped at a `during` checkpoint, stop there. Approvals are records only the PI (or a campaign
  the PI delegated the checkpoint to) makes.
- Kill criteria that fire mid-step are recorded as the procedure says; they don't wait for a hand-off.

## 4. Stop and report

End every `/advance` with a verification summary:
1. **What ran and what changed** — the procedure, files written, runs launched (ids), the outcome reported
   and where `arlotope move` said the study went.
2. **What to verify** — the 2–4 artefacts worth the PI's read (e.g. the novelty verdict, decisions.md's
   riskiest decision, the ledger entry, the draft's claims).
3. **What the next `/advance` would do** — so "continue" is an informed yes.

Headless (`ARLOTOPE_RUN_ID` set): the summary is your final message, and the run footer's `next` is the
command `arlotope move` printed (`/<procedure> <slug>`), or empty. `needs_pi=none`, or — when the study waits
at a checkpoint — that checkpoint's id from the brief, with `--data study=<slug>`.

Then the standard write-back (the notebook — hard rule 11 per session).
