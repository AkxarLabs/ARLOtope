# Compete — pursue a fixed target

<!-- arlotope:contract (generated by `arlo docs` from workflow/) -->
**First, load the brief:** `arlo.py brief compete [--study <slug>]`; skip when `ARLOTOPE BRIEF /compete` is already supplied. It states how to finish, what to produce and show the PI, and the PI's additions and checkpoints.
**Read first:** `AGENT-GUIDE.md` — "Target-driven projects (/compete)".
<!-- /arlotope:contract -->
For a **task with a straightforward target** (beat a benchmark, hit a metric, climb a
leaderboard, reach a KPI), `/compete` spins off a project aimed at it and sets up the
**iterate-toward-target loop** — run experiments, fan out ideas in-project, log everything,
move the metric. It reuses the whole project engine (staged scale, frozen eval, budgets,
ledger, git, `/research-loop`) and **skips the paper layer** (no
`/ideate→/lit-review→/scope→/propose`, no novelty gate, no headline-hypothesis boundary).
Host-agnostic — Kaggle is one instance; the agent learns and records the task's specifics
itself in `TARGET.md`. Use when the success criterion is a number, not a claim.

## 1. Short interview — establish the target

*Optional first:* if the target is fuzzy, run `/discuss target [task]` to grill the PI and
research the task before this interview — its session doc lists the answers below, so this step
transcribes rather than re-asks. *Headless (launched from the dashboard):* ask one question per turn —
`AskUserQuestion` when it has discrete options, else prose as the turn's final message; the PI answers
in the dashboard and the session resumes. Nothing you write records an approval — approvals are the PI's.

A study made by `/compete` uses the lab's **`target`** workflow; its checkpoints (e.g. on sending an
output to an external scorer, and on choosing the final output) are in the brief. This interview is
the PI's go-ahead for the project — write its outcome into `IDEA.md` (no separate proposal). Establish:

- **The task & target** — name, URL (if any), the **done-condition** (e.g. "public ≥ 0.90",
  "RMSE < 0.42 on the grader", "top-10 by the deadline"), and the **deadline** (if any).
- **Metric + direction** (maximize | minimize).
- **Data/resources** — where they live, how to fetch/authenticate (command + env-var key names,
  never values); train vs. held-out/unlabeled input.
- **Scoring** — **internal** (computed locally, no data leaves the lab) or **external** (send an
  output to a scorer/leaderboard, read a score back). If external: how (CLI / HTTP call / grader
  script — fills `target.scoring.score_command`), and the scorer's rate limit (the PI states how
  many reads they allow when approving external scoring).
- **Output contract** (only if scored on an artifact you produce) — file/format, id + target
  column(s), exact expected row count.
- **Rules/constraints** — allowed external data, pretrained-model/runtime limits, account/team
  rules. These bind like `SYSTEM.md`.
- **Budgets** — per-stage caps and the total compute (minutes, GPU-hours) for `control.yaml`
  `budgets`.
- **Exploration** — whether the PI wants the loop to expand the frontier by itself. That needs
  `loop.mode: explore` and `loop.explore_max_expansion_rounds` > 0, which are PI-owned: ask the PI to
  set them (Settings, or `/configure`). Until then `/improve explore` and `/research-loop` expand nothing.

## 2. Scaffold the project

If the PI already has a code repo, wrap it instead (§4). Otherwise:

1. **File the study:** `arlo.py new <slug> --title "<title>" --workflow target`. It starts at the
   workflow's first step. Then write `studies/<slug>/IDEA.md` from `templates/idea/`, carrying the PI's
   target and the interview verbatim (leave its `state:` line to the kernel).
2. **Scaffold:** `tools/spawn_project.py --slug <slug> --title "<title>" --project-type target-driven
   --overlay compete --skip-guard` (the target workflow offers no `/spawn-project`, hence `--skip-guard`).
   It copies `templates/project/` with the `templates/compete/` overlay, substitutes the placeholders and
   records the project path. Append the overlay's `control.target.yaml` to `control.yaml`, then delete it.
3. Fill **`TARGET.md`** (PI-owned brief) and the `control.yaml` `target:` block from the
   interview: `metric`, `direction`, `done`, `deadline`, the `output` contract (or `null` for a
   local-metric target), `scoring` (`read_back`, `external`, and `score_command` if `command`).
   Set `budgets` exactly as `/spawn-project` does, from what the PI said in the interview.
   Keep `eval_frozen: true` (the metric + local split is the frozen eval).
4. Fill **`PLAN.md`** (the engine drives off its rows — `/experiment`, `/advance`,
   `/research-loop`). Frozen evaluation = the metric + the local validation split that mirrors the
   scorer + the held-out test (the external scorer, if any); **Headline hypothesis = the target
   itself** ("reach `<done>`"); kill criteria; and a staged experiment table seeded with at least
   the SMOKE row and the first real baseline line(s). Budgets reference `control.yaml`.
5. Initialize and verify exactly as `/spawn-project` does (git, `uv sync`, smoke, tests,
   `check_project.py`; green → commit with `uv.lock`, red after `experiment.max_debug_depth` fixes → leave
   uncommitted and tell the PI), plus `scripts/check_output.py runs/<run_id>/<file>` when there is an
   output contract (the toy emits a valid one). The first planned experiment (`/experiment <slug>`) is next.
6. Append a lab notebook entry.

## 3. Iterate toward the target

The loop, the selection discipline and the checkpoints (external scoring, the final output) are in
[Iterate and checkpoints](references/iterate.md).

## 4. Adopting an existing repo

Don't restructure it, wrap it: file the study as in §2 step 1, then follow `/adopt`'s "Adopting a repo"
(its `references/structured.md`) with the overlay: copy in `templates/compete/`,
set `package:` in `control.yaml` when `src/` holds several packages, and adapt `experiment.py` to call
the repo's entry point and `write_output(...)` the scorer's artifact. Fill TARGET.md and PLAN.md as in §2.

## 5. Report

Target + done-condition, where the project lives, smoke/output-check/test status, the
`control.yaml` `target:` and `budgets` summary, the workflow's checkpoints, and the exact next
command (usually `/experiment <slug>`, or a `LOOP_BRIEF.md` for the PI to approve for `/research-loop`).
