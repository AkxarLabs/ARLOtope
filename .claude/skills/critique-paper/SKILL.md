# Critique Paper

<!-- arlotope:contract (generated by `arlo docs` from workflow/) -->
**First, load the brief:** `uv run --with pyyaml python arlo.py brief critique-paper --study <slug>`; skip when `ARLOTOPE BRIEF /critique-paper` is already supplied. Follow its task ownership, additions and checkpoints.

**It must produce:**
- studies/<slug>/critiques/ or paper/reviews/ report: per-lens scores, meta-review, action items

**Show the PI** (`python tools/artifact.py publish --title "…" --file <path>`): the critique summary — per-lens scores and the top action items. Publish once per milestone. Use `--question "…" --choices "A;B"` for feedback, never approval.

**Read first:** `AGENT-GUIDE.md` — "The back half: analysis, writing, review and back".
<!-- /arlotope:contract -->

Ensemble sizes, anchors, and cycle caps come from `lab/config.yaml` (`critique.*`).
Lens definitions + the calibration block live in `templates/review/critique-lenses.md`.

## 1. Detect mode & materialize the paper to a file

- **Own-draft mode** (argument is a study slug with `studies/<slug>/paper/`): the paper file is
  the compiled PDF (preferred) or `studies/<slug>/paper/main.tex`. Reviews go to
  `studies/<slug>/paper/reviews/critique-<date>/`. For a paper under review the canonical entry is
  `/review-paper` (its blocking Part A claims audit runs first); a standalone own-draft
  critique is advisory.
- **External mode** (arXiv id / URL / PDF path): download the actual artifact — for an
  arXiv id, the PDF (`https://arxiv.org/pdf/<id>`) to
  `studies/<slug>/critiques/sources/<bibkey>.pdf`; fall back to saved extracted text
  (`<bibkey>.md`) only when no PDF is obtainable, noting in the critique header that the
  source was extracted text (reviewers must read the paper, not a lossy summary). Reviewer
  files + meta-review go to `studies/<slug>/critiques/<bibkey>/` (one file per lens); the
  distilled verdict goes to the lit-review note. With no study, use `lab/reviews/<bibkey>/`.

## 2. Spawn the reviewer ensemble (fresh-context invariant)

- Ensemble size: `critique.ensemble_external` lenses (those in `templates/review/critique-lenses.md` not
  marked *own drafts*) for external papers; `critique.ensemble_own_draft` (every lens there) for
  own drafts.
- Spawn one `fresh-context-reviewer` subagent per lens, **in parallel**. Each prompt
  contains ONLY: the paper file path (the `process` lens also gets the project's run-trail paths,
  from `arlo.py studies --json`), the lens name + its definition and the calibration
  block (paste both from `critique-lenses.md`, **substituting the anchor value with
  `critique.score_anchor_human_mean`** so a re-tuned anchor actually takes effect), and the
  output file path.
- **HARD RULE: never include your own summary, opinion, or context about the paper in a
  reviewer prompt.** The reviewers' value is that they read cold (the fresh-context
  invariant).

## 3. Meta-review

Fill `templates/review/meta-review.md` yourself from the reviewers' files:
- Scores aggregate as **median (min–max)** per dimension — never mean.
- Grade every weakness against the **taste rubric** (`critique-lenses.md`): **LOAD-BEARING** points
  drive decisions; **GENERIC** and **MISDIRECTED** points are noted but carry no action items.
- Collect every `FATAL FLAW:` line into the veto table. **Any unrefuted fatal flaw
  blocks accept**; an override requires a written refutation with specific evidence.
- **Oversight** (own-draft mode): a fatal-flaw refutation is written by the same session
  that wrote the paper, yet it unlocks accept — so at `oversight.level` ≠ off, spawn an
  `overseer` `support` check on **every refutation that would flip a fatal flaw to
  refuted** (statement = the refutation; evidence = the cited artifact paths). At `strict`,
  additionally grade each fatal flaw itself with an `overseer` `critique-taste` check. An
  overseer-rejected refutation does not override the veto.
- Synthesize: where the lenses agree, where they conflict, and which conflict matters for the decision
  at hand.
- Own drafts: write numbered action items that are specific and checkable ("add the n=3 seed band to
  Table 2"), never general ("improve clarity").
- Write the meta-review file beside the reviewer files.

## 4. Finish by mode

- **Own draft**: report median Overall, decision, fatal flaws, and action items. The caller
  (`/review-paper`) or the step's own procedure acts on them.
- **External**: distill into the study's `lit-review.md` paper notes. The critique file is the deep
  record; the note gets the verdict and what it means for *our* positioning (e.g. "claimed SOTA is
  unsupported at our scale; the baseline is weaker than it appears"). Report the one finding that most
  changes a decision, not a summary of every lens.

This procedure runs alongside a step's own procedure: report an outcome only if the brief lists outcomes
for you; otherwise just finish.
