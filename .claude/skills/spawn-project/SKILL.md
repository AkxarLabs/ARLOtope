# Spawn Project

<!-- newts:contract (generated by `newts docs` from workflow/) -->
**First, load the brief:** `uv run --with pyyaml python newts.py brief spawn-project --study <slug>` — skip it if a `NEWTS BRIEF /spawn-project` block is already in your context. It says where the study stands, the PI's own instructions for this work, and the checkpoints.

**Finish by reporting one outcome** — `done`, `scaffold-failed`, `park`, `kill` — with `uv run --with pyyaml python newts.py move <slug> <outcome> --note "…"`. The study's workflow decides where it goes (the brief lists each outcome's destination); never edit lab/REGISTRY.md or lab/journal.jsonl.
<!-- /newts:contract -->

Output: a runnable, committed project repo at `<projects_root>/<slug>` — **outside the hub**,
independently cloneable.

## Procedure

0. **Existing repository:** read the study's registered project location and `IDEA.md` first. An attached
   project keeps its code, environment and runner. Do not run the scaffolder or replace its registry
   path. Inspect the existing setup and satisfy the proposal with it. Add tracking files only when
   requested, explaining any additions; if that choice is unresolved, ask one focused question. Report
   `done` only once the agreed setup is ready and verified. The remaining steps create a **new** project.

1. Read `studies/<slug>/proposal.md` and, if they exist, `decisions.md` and `lit-review.md`. If there is no
   proposal, say so and report `park`.
2. Resolve `lab.projects_root` from `lab/config.yaml` (default `../newts-lab-projects`,
   relative to the hub). If the container directory doesn't exist, create it with a
   one-paragraph README ("Projects spawned by the ARLOtope at <hub path>; each
   is an independent git repo — `newts status` in the hub lists them").
3. **Scaffold via the tool** (mechanical copy/substitute — Windows-BOM-safe). After deciding the
   type/domain in 3b (below), run:

   ```bash
   uv run --with pyyaml python tools/spawn_project.py --slug <slug> --title "<title>" \
     --project-type <type> [--domain <d>] [--overlay compete]
   ```

   It copies `templates/project/` → `<projects_root>/<slug>` with `{{slug}}`/`{{title}}`/`{{date}}`/
   `{{hub_path}}` substituted as **UTF-8 with no BOM** (`hub_path` forward-slashed so `control.yaml`
   stays valid YAML on Windows), drops runtime cruft (`.pytest_cache`/`.bus`/`__pycache__`/stale
   `runs/` dirs), applies the project-TYPE card + `control.yaml` `project_type` (`--project-type`) +
   optional domain profile (`--domain` → `DOMAIN.md`) + optional target-driven overlay
   (`--overlay compete`), and copies `lab/SYSTEM.md` → `SYSTEM.md` if present. The vendored
   `.claude/skills/` (grilling/domain-modeling/grill-with-docs) and `.codex/` role files ship in every
   project (no substitution) so any agent (Claude or Codex) has them standalone, and it records the
   project's path with the kernel. It **refuses** (exit 1) a study that isn't standing where its project
   is made, and a `<slug>` that already has commits or a non-empty `runs/` (a reused slug overwrites a
   recorded kill/result — the successor needs a distinct slug that links the old one in its triage
   notes). On a refusal, stop, report no outcome, and tell the PI what it printed. It does
   **not** fill `PLAN.md`/`control.yaml` — those judgment steps are below (keep
   the `project_pkg` package name unless publishing standalone). `NOTES.md` ships empty (`(none yet)`)
   and accretes lessons as the project runs.
3b. **Select & apply the project TYPE** (the methodology axis — bound here, at spawn). Read the
   proposal (`studies/<slug>/proposal.md`, `decisions.md`, the frozen eval protocol) and
   the cards in `{{hub_path}}/templates/project-types/*/TYPE.md`. Pick the best-fit type —
   <!-- newts:project-types (generated by `newts docs` from workflow/) -->`empirical` · `ml` (default) · `simulation` · `target-driven` · `theory`<!-- /newts:project-types --> (every folder in `templates/project-types/`) — plus, for a non-ML
   field, an optional **domain profile** from `templates/domain-profiles/` (or draft one). If none
   fits, propose a NEW type (a `TYPE.md` card) — a PI-owned act. **Present the chosen {type, domain}
   to the PI and get confirmation** before proceeding (it shapes the whole project, like the
   proposal itself; under a campaign the PI approved, decide within its bounds; *headless without a
   campaign*: ask it as ONE `AskUserQuestion` — options = the candidate {type, domain} pairs, your
   pick first — and continue when resumed with the answer). This decision is
   PI-confirmed and passed to step 3's `spawn_project.py` via `--project-type` / `--domain` /
   `--overlay` (step 3 does the copying). You still set by hand:
   - `control.yaml` `runner:` — `python-import` for `ml`/`target-driven`/Python work; `shell-command`
     + `runner_command:` for an R/Stata/Julia/proof-checker tool (that path writes the metrics dict to
     `$RUN_DIR/result.json` — same artifact contract, so hard rule 1 holds across languages).
   - `target-driven`: pass `--overlay compete` (what `/compete` does) — or just run `/compete` for that
     type instead of `/spawn-project`.
   - Non-`ml` type: write the **smoke** in the type's shape (a tiny regression / one sim draw / a
     proof-checker no-op) so step 7's smoke + `check_project.py` pass. `ml` keeps the base toy.
4. **Configure `control.yaml`** (the project's end-to-end run config): fill
   budgets (including `total_minutes`, and `gpu_hours` if the proposal gives GPU-hours), the `data:` provenance block, seeds and loop values from the proposal, and copy the proposal's frozen Analysis plan into PLAN.md. Budgets are instructions the Compute panel tracks, not limits a script enforces. Full-scale runs are not authorized here: they wait for their own checkpoint, if the workflow has one (the stage brief says, with the PI's note).
5. Fill `PLAN.md` from the proposal: frozen eval protocol (including the
   **headline hypothesis** — the central claim, the explore-mode autonomy boundary), kill
   criteria, the staged experiment table, the ablation plan (budgets live in control.yaml —
   reference, don't duplicate). Leave `control.yaml` `loop.mode: execute` unless an
   `/autopilot` campaign the PI approved chose `explore` for spawned projects (then set it + the caps).
6. Add the project's real dependencies to `pyproject.toml` (minimal set; pin via lock).
7. Initialize: `git init`, then `uv sync`, then run the smoke pipeline:
   - `uv run python scripts/run.py --config configs/experiments/exp-001-smoke.yaml`
   - `uv run pytest tests/`
   - `uv run --with pyyaml python scripts/check_project.py` (readiness lint — exit 0)
   Commit (with `uv.lock`) only once all pass ("scaffold: spawn from ARLOtope template, smoke green").
   If any of `uv sync` / smoke / tests / check_project fail: debug up to `experiment.max_debug_depth`
   attempts; still red → leave the directory **uncommitted** — never commit a red scaffold.
8. Append a lab notebook entry.
9. **Report the outcome** (`newts.py move <slug> <outcome> --note "…"`):
   - `done` — the scaffold is committed and green. Note: the project path and the first planned
     experiment.
   - `scaffold-failed` — still red after the debug budget. Note: which check fails and the error.
   - `park` / `kill` — only if building the project showed the plan can't run here (e.g. the data or
     hardware it needs isn't available). Note: why.

   Then tell the user the project path, smoke/test status, a `control.yaml` summary and the first planned
   experiment. If `newts move` says the study waits for the PI, present that and stop (headless:
   `needs_pi=<that checkpoint's id>`, or `needs_pi=scaffold-failed`).

## Rules

- The template's toy experiment stays until the first real experiment replaces it — the smoke test must always pass.
- Never start domain experiments in the same run as scaffolding; spawn cleanly, then the next step's procedure runs them.
