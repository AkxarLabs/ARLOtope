# Review Paper

<!-- newts:contract (generated by `newts docs` from workflow/) -->
**First, load the brief:** `uv run --with pyyaml python newts.py brief review-paper --study <slug>` — skip it if a `NEWTS BRIEF /review-paper` block is already in your context. It says where the study stands, the PI's own instructions for this work, and the checkpoints.

**Finish by reporting one outcome** — `done`, `revise`, `more-experiments`, `park`, `kill` — with `uv run --with pyyaml python newts.py move <slug> <outcome> --note "…"`. The study's workflow decides where it goes (the brief lists each outcome's destination); never edit lab/REGISTRY.md or lab/journal.jsonl.

**It must produce:**
- paper/reviews/ round reports + meta-review with a verdict (accept|revise|reject)
- author response + revisions

**Show the PI** (`python tools/artifact.py publish --title "…" --file <path>`): each round's meta-review — the verdict and its action items. One artifact for what they would genuinely want to see — not a running commentary. A decision you need takes `--question "…" --choices "A;B"` (the answer comes back to this run); it is never an approval.

**Read first:** `AGENT-GUIDE.md` — "The back half: analysis, writing, review and back" (it binds exactly like AGENTS.md).
<!-- /newts:contract -->

Input: a drafted paper in `studies/<slug>/paper/`. Output: `studies/<slug>/paper/reviews/review-N.md`
consolidating the cycle, and an outcome. Cycle cap: `critique.max_review_cycles` (count the existing
`review-N.md` files).

## Part A — Claims audit (mechanical, blocking)

1. **Figures in sync:** `uv run --with pyyaml python .claude/skills/make-figures/tools/sync_figures.py <slug> --check` —
   a stale (project regenerated, not re-synced) or hand-edited hub figure is a blocking FAIL;
   re-run `.claude/skills/make-figures/tools/sync_figures.py <slug>` then re-check before continuing.
2. Run `uv run --with pyyaml python checks/audit_claims.py studies/<slug>/paper --check-commits --scan-novelty --rel-tol <critique.claim_rel_tol>`.
   - Any **FAIL** blocks. (FAIL includes the completeness scan: any numeral in main.tex body prose
     with no `% CNNN` annotation — a number with no claims entry.)
   - Any **MANUAL** → verify each by hand against the stated derivation now; an
     unresolvable MANUAL is a FAIL.
   - Any **Novelty WARN** (`--scan-novelty` — a priority/superiority claim: SOTA / "first to" /
     "outperforms all" / unprecedented, with no `\cite` or `% Cnnn/Nnnn` backing) → resolve each
     now: cite the closest prior work it's positioned against, add a `% Nnnn` lit-review pointer,
     or soften the wording. An unresolved one is a FAIL — this is the discovery-vs-rediscovery
     gate (the field's most public failures were rediscovery shipped as discovery). It must trace
     to the `/lit-review` novelty verdict, exactly as a number must trace to an artifact.
   - **Paper-integrity audits (blocking):**
     - `checks/audit_multiseed.py studies/<slug>/paper` — headline claims (`headline: true`) carry ≥
       `seeds.multi_seed_n` distinct seeds (hard rule 6); a `multi_seed_waiver` routes to MANUAL.
     - `checks/audit_ablation_coverage.py studies/<slug>/paper` — every planned ablation ran / was
       waived / routed, none silently dropped.
     - `checks/audit_eval_discipline.py studies/<slug>/paper` — the frozen protocol defines validation +
       held-out test and no headline claim reports a validation-selected metric (hard rule 5).
     Exit **1 = FAIL** · **2 = MANUAL** (resolve by hand; unresolved = FAIL) · 0 = clean.
3. Run `uv run --with pyyaml python .claude/skills/lit-review/tools/s2.py verify studies/<slug>/paper/references.bib --threshold <writing.citation_match_threshold>` —
   **any nonzero exit blocks**: NOT-FOUND, RETRACTED, *and* MISMATCH (below-threshold title
   or wrong year — the near-miss-fabrication case).
4. **Cite-from-lit-review (mechanical):**
   `uv run --with pyyaml python .claude/skills/lit-review/tools/s2.py citecheck studies/<slug>/paper --threshold <writing.cite_grounding_threshold>` — every `\cite`
   must resolve to a `references.bib` entry (**DANGLING** → exit 1, blocks, LaTeX would fail too)
   and to a `studies/<slug>/lit-review.md` note (**UNGROUNDED** → exit 2, the by-hand confirm list:
   add the paper to the lit review with a note, or cut the citation).
5. Manual checks the scripts can't do:
   - Spot-confirm variance is *reported* for headline numbers and the narrative doesn't quietly lean on
     a test-set-selected choice.
   - **Phantom-experiment sweep.** AI-written papers hide fabricated experiments in ablation and
     analysis subsections, not in the main results, and especially after revision rounds. Walk those
     subsections claim by claim against the project's ledger: for each experimental claim, find the
     `EXPERIMENT_LOG.md` entry and the `runs/registry.jsonl` line, and check that the configuration
     described is the one that ran. Spot-check that at least two figure scripts in the project repo's
     `scripts/figures/` are committed and regenerate their figures. At `oversight.level` ≠ off, spawn
     an `overseer` `support` check per ablation/analysis experimental claim (statement = the claim;
     evidence = `EXPERIMENT_LOG.md` + `runs/registry.jsonl` paths) — the judgment check most exposed
     to author rationalization, and you wrote (or just saw written) this paper.

**A paper failing any Part A check gets no qualitative review:** write the failure table to
`reviews/review-N.md` and report `revise` (below).

## Part B — Fresh-context critique ensemble

Invoke `/critique-paper <slug>` (own-draft mode: full ensemble, meta-review with
median scores and minority veto). Do not review the paper yourself — you've seen it
written; that's exactly the bias the ensemble exists to remove.

## Part C — Author response

1. Write `studies/<slug>/paper/reviews/review-N.md`: pointer to the critique directory, the
   meta-review's score table, decision, veto table, and its action items verbatim.
2. **Author-response triage** (`templates/review/response.md` → `reviews/response-N.md`): every action
   item gets ACCEPT / REBUT / NEEDS-EXPERIMENT **with evidence**.
   - **Validate feedback; never just obey it.** Reviewers confabulate too. Revising to satisfy a wrong
     critique, or inventing support for a demanded ablation, is the documented failure mode of
     review-driven revision.
   - Apply the taste rubric (`critique-lenses.md`): GENERIC and MISDIRECTED items earn no action.
   - A good **REBUT** cites specific evidence: the table, the run, the lit-review note. "We disagree"
     is not a rebuttal, and a rebuttal without evidence doesn't count.
   - A good **ACCEPT** names the concrete change and where it goes.
   - A good **NEEDS-EXPERIMENT** names the experiment, its pre-written criterion, and what it would
     settle.
   - Items rebutted twice but re-raised, and anything touching frozen settings, escalate to the PI.
3. **Oversight pass** (`oversight.level` ≠ off): spawn one `overseer` subagent per
   triage verdict — `critique-taste` on the original item, `support` on the verdict's
   evidence (paths only, never your reasoning). An overseer-rejected verdict is redone
   against the cited evidence or escalated — the circuit-breaker between a wrong
   review point and a wrong "improvement".

## Report the outcome

1. Update the notebook with scores, the triage tally, and the outcome. Emit
   `uv run python tools/lab_bus.py emit review_verdict --idea <slug> --detail "median <X>, <outcome>"`.
2. Report one outcome:
   - `more-experiments` — any NEEDS-EXPERIMENT item. First append the new rows to the project's
     `PLAN.md` (criteria written now), commit the project, and emit
     `uv run python tools/lab_bus.py emit replan --idea <slug> --detail "review NEEDS-EXPERIMENT"`.
     New claims require new runs; nothing gets "addressed" in prose that needed an experiment. Note:
     the experiments and the `response-N.md` path.
   - `revise` — a Part A failure, or ACCEPT items remain. Note: the `review-N.md` / `response-N.md`
     path that holds the worklist.
   - `done` — meta-review **accept** AND zero unrefuted fatal flaws. Note: median Overall and the
     `review-N.md` path.
   - `park` — `critique.max_review_cycles` cycles reached with gaps remaining, or a **reject** the
     action items cannot rescue. Note: the residual gaps, so the PI can decide.
   - `kill` — only on the PI's word.
3. If `newts move` says the study waits for the PI, present the PDF and the meta-review and stop
   (headless: `needs_pi=<that checkpoint's id>`, with `study=<slug>`). Only the PI (or a campaign the
   PI delegated that checkpoint to) approves it; never write anything that claims an approval — a line
   in a review file approves nothing. The run footer's `next` is what `newts move` printed.
